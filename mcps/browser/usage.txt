브라우저 페이지 확인 MCP

도구 이름: browser_fetch_rendered
루트 run.cmd로 뉴스, 웹검색, 일반 페이지 읽기와 함께 등록된다.
Microsoft Edge를 화면에 표시하지 않고 실행한다. Edge와 Node.js가 필요하다.
Node.js는 이 컴퓨터의 Codex 제공 런타임 경로를 사용한다.
추가 패키지나 API 키는 필요 없다.

기능:
  HTTP 301/302/307/308 및 JavaScript 이동을 브라우저가 처리한다.
  JavaScript 실행 후 내용이 안정될 때까지 기다린다.
  필요하면 CSS 선택자가 나타날 때까지 기다린다.
  페이지를 순차적으로 스크롤하여 lazy loading을 유도한다.
  제목, 본문, 링크, 최종 URL, 이동 경로, 제한 도달 여부를 반환한다.
  이전에 보이던 내용이 사라지는 가상 목록은 일부 내용을 보존하지만 전체 수집은 보장하지 않는다.

주요 인수:
  url: 공개 HTTP/HTTPS 주소
  wait_seconds: 최초 로딩 최소 대기, 기본 2초, 최대 10초
  wait_for_selector: 선택 사항, 예: article 또는 #content
  scroll_steps: 기본 12회, 최대 40회
  timeout_seconds: 기본 45초, 최대 90초
  max_chars: 기본 12000자, 최대 40000자

질문 예시:
  browser_fetch_rendered로 이 URL을 열고 리디렉션과 lazy loading을 처리한 뒤 내용을 요약해줘: https://example.com
  browser_fetch_rendered에서 scroll_steps=30, timeout_seconds=60으로 페이지를 확인해줘: https://example.com

무한 스크롤은 끝이 없으므로 시간 또는 횟수 제한에 도달하면 중단한다.
stop_reason, timed_out, truncated, selector_found를 확인하고 전체 내용을 읽었다고 단정하지 않는다.
내부 스크롤 영역, iframe, 버튼을 눌러야 나타나는 내용은 자동 처리하지 않는다.
로그인, CAPTCHA 우회, 보안 경고 우회, 파일 다운로드는 지원하지 않는다.
사용자의 기존 브라우저 프로필과 로그인 정보를 사용하지 않는다.
매 요청에 별도 임시 프로필을 사용하며 종료 후 정리한다.
URL과 페이지 요청은 해당 사이트에 전송된다.
사이트 접근 제한이나 브라우저 자동화 차단이 있으면 내용을 읽지 못할 수 있다.
